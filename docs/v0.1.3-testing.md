# v0.1.3 on-device test checklist

This checklist is for the unreleased `agent/v0.1.3-reliability-matching` branch. Automated Lua tests are required before merge, but KOReader UI, filesystem, network, updater, and live-provider behaviour should also be exercised on a real device before publishing the stable GitHub Release.

## 1. Installation / upgrade safety

- [ ] Exit KOReader completely.
- [ ] Back up `koreader/settings/metadata_scraper.lua`.
- [ ] Copy the development plugin folder over the existing `metadata_scraper.koplugin` folder.
- [ ] Restart KOReader.
- [ ] Confirm Metadata Scraper loads without a plugin error.
- [ ] Confirm existing provider credentials/settings are still present.
- [ ] Open **About** and confirm the displayed version is `0.1.3`.
- [ ] Confirm `lib/diagnostics.lua` and `lib/version.lua` exist in the installed plugin folder.
- [ ] Confirm older settings that pre-date `batch_skip_matched` still load and default that option to enabled.

## 2. Provider diagnostics and readiness UI

Open **Metadata Scraper → Provider accounts → Test provider connections…** and the **Providers** dialog.

- [ ] Hardcover reports authenticated/OK with a configured token.
- [ ] Google Books reports that the API key is accepted.
- [ ] Open Library reports reachable.
- [ ] Amazon reports OAuth OK when valid credentials are configured.
- [ ] A deliberately unconfigured provider reports a useful failure instead of crashing.
- [ ] Diagnostic messages never display credential secrets or full tokens.
- [ ] Open Library shows a credential-free ready state without making a test request merely to open the Providers dialog.
- [ ] Hardcover shows token missing/configured state appropriately.
- [ ] Google Books shows credentials missing when no key is configured.
- [ ] Amazon shows credentials missing when the required account fields are absent.
- [ ] After Amazon has a reusable OAuth token, its status can indicate that the token is cached.
- [ ] If Google enters a real rate-limit cooldown naturally, the Providers dialog shows an approximate remaining cooldown rather than simply saying ready.

## 3. Sanitized support diagnostics

Generate **Save support diagnostics…** after running at least one successful provider test and one harmless failed/unconfigured provider test.

- [ ] A support file is created under KOReader's Metadata Scraper cache directory.
- [ ] The UI shows the saved path.
- [ ] The file contains plugin version and provider enabled/configured state.
- [ ] The file contains useful recent sanitized events.
- [ ] The file does **not** contain the complete Hardcover token.
- [ ] The file does **not** contain the complete Google API key.
- [ ] The file does **not** contain Amazon Credential ID, secret, or Partner Tag.
- [ ] URLs containing query parameters are represented without their query values.
- [ ] Deleting the generated support file has no effect on plugin settings or normal operation.

## 4. Hardcover regression

- [ ] Search `Dungeon Crawler Carl`.
- [ ] Confirm Hardcover returns results.
- [ ] Confirm no `Malformed Authorization header` error.
- [ ] Confirm both a raw Hardcover token and an already-prefixed `Bearer ...` token work if practical to test.
- [ ] Preview the selected result and confirm title/author/series/cover information looks sensible.
- [ ] If Hardcover supplies recognizable edition/format data in its search document, confirm it appears without breaking results that omit it.

## 5. Automatic ISBN detection

Choose an EPUB known to contain an ISBN identifier.

- [ ] Open **Fetch metadata**.
- [ ] Confirm ISBN is pre-filled automatically where KOReader exposes it in `identifiers`.
- [ ] Search without manually changing the detected ISBN.
- [ ] Confirm an exact ISBN result scores 100% when there is no explicit edition-format contradiction.
- [ ] Test at least one EPUB without a usable ISBN and confirm title/author search still works normally.
- [ ] Confirm an invalid checksum 10/13-digit value is not promoted to an exact ISBN.

## 6. Match conflict safeguards, confidence classes, and edition awareness

Use disposable searches/EPUB metadata where you can deliberately introduce contradictory evidence.

- [ ] Exact matching ISBN remains 100% when provider format is unknown or consistent with an ebook.
- [ ] Exact matching ISBN is labelled **Exact** only when there is no explicit hard edition conflict.
- [ ] A high-quality title/author match without an exact ISBN can be labelled **Strong**.
- [ ] A middling clean match can be labelled **Possible**.
- [ ] A candidate with a different valid ISBN is visibly marked with **ISBN conflict**, labelled **Weak**, and remains far below the 90% batch threshold.
- [ ] A strong language conflict reduces confidence below automatic acceptance.
- [ ] A clearly different author reduces confidence rather than being ignored.
- [ ] A clearly conflicting series reduces confidence rather than being ignored.
- [ ] Hard conflicts do not receive a misleading Strong confidence label merely because other text is similar.
- [ ] A provider result explicitly identified as **audiobook** for an EPUB is marked with **format conflict**, labelled **Weak**, and remains at or below 35%.
- [ ] A provider result explicitly identified as **paperback/hardcover/print** for an EPUB is marked with **format conflict**, labelled **Weak**, and remains at or below 65%.
- [ ] An exact ISBN plus an explicit contradictory print/audiobook format is downgraded for manual review rather than blindly treated as Exact.
- [ ] Unknown/omitted provider format is neutral and does not create a false conflict.
- [ ] Known compatible ebook/Kindle format can contribute a **format match** reason.
- [ ] Format/edition is shown in preview and Last match details when available.
- [ ] A conflict result remains available for manual inspection instead of crashing or silently disappearing unless the provider record itself is malformed.
- [ ] Confidence appears both in search results and in the detailed preview.
- [ ] After Apply, **Last match details** retains the recorded confidence class and known edition evidence.

## 7. Author comparison normalization

Use searches where provider/local author text differs only in ordering/punctuation.

- [ ] `Matt Dinniman` and `Dinniman, Matt` compare as the same author signal.
- [ ] Multi-author punctuation/order variants do not create an obvious false author conflict.
- [ ] Provider/displayed author text is **not rewritten** merely because comparison normalization is used.
- [ ] A genuinely unrelated author is still penalized as an author conflict.

## 8. Cross-provider deduplication

Enable at least two providers that return the same edition/book.

- [ ] Search a common book.
- [ ] Confirm identical ISBN results do not occupy multiple visible result slots.
- [ ] Confirm the preferred result shows `+N` when duplicate providers were merged.
- [ ] Open the result and confirm **Also found on** lists the other provider(s).
- [ ] Confirm distinct books that merely share a title are not incorrectly merged.

## 9. Match explanations

- [ ] Exact ISBN result shows an ISBN match reason.
- [ ] Exact title + author result shows appropriate title/author reasons.
- [ ] Language/series/format signals appear when available.
- [ ] Conflict reasons appear when contradictory evidence is present.
- [ ] Scores remain conservative enough for the 90% default batch threshold.
- [ ] The confidence class complements rather than replaces the detailed match-reason text.

## 10. Broader search fallback

Use a book whose embedded author text is noisy or intentionally alter the author field.

- [ ] Search with valid title but non-matching author.
- [ ] Confirm the plugin can recover through its one-time title-only fallback when the strict provider search returns no result.
- [ ] Confirm fallback does not loop or repeatedly query indefinitely.

## 11. No-results and crash isolation

Search an intentionally nonsensical title and exercise at least one harmless provider failure.

- [ ] No-match dialog lists provider result counts and/or provider errors.
- [ ] Rate-limit/authentication errors are distinguishable from a genuine zero-result response.
- [ ] One provider failing does not prevent another enabled provider from returning results.
- [ ] A malformed/unexpected provider response, if naturally encountered, produces a controlled failure rather than exiting KOReader.
- [ ] A failed metadata read/write does not modify the EPUB source file.

## 12. Google Books cooldown

Only test this naturally if Google returns a real quota/rate-limit response; do not intentionally burn API quota just to force a 429.

- [ ] Normal Google search works with the configured API key.
- [ ] If a rate limit occurs naturally, the error reports a cooldown rather than repeatedly hammering the API.
- [ ] Generic HTTP retry logic does not override Google's provider-specific 429 cooldown.
- [ ] The non-network provider status reflects an active cooldown while it is in force.

## 13. Amazon Creators API

If Amazon credentials are available:

- [ ] Enter the credential version shown for the credential (`3.1`, `3.2`, or `3.3`).
- [ ] Run provider diagnostics and confirm OAuth succeeds.
- [ ] Search the configured marketplace.
- [ ] Change only the marketplace and confirm searches continue working without requiring credential re-entry.
- [ ] Confirm changing Amazon credentials/version and saving them does not reuse a stale token.
- [ ] Confirm Amazon errors are readable and do not expose the secret.
- [ ] Confirm provider status changes from configured/not tested to a cached-token-ready state after successful authentication.
- [ ] When Amazon returns Binding/Edition data, confirm it is visible in the match preview/provenance.
- [ ] If Amazon returns `Kindle Edition`, confirm it is treated as ebook-compatible rather than as a conflict.
- [ ] If an obvious Paperback/Hardcover result is returned, confirm it is not eligible for automatic EPUB batch apply.

For an older settings file where `amazon_credential_version` is blank:

- [ ] Confirm legacy endpoint inference still allows the old configuration to operate where it previously worked.

## 14. HTTP retry behaviour

Do not deliberately attack or overload providers. These checks should use a controlled test endpoint/network interruption if practical, or rely on automated regression coverage otherwise.

- [ ] A transient GET/download failure can retry once.
- [ ] HTTP 502/503/504 are eligible for the single retry.
- [ ] HTTP 429 is not blindly retried by the generic layer.
- [ ] Ordinary POST requests are not duplicated by the generic retry layer.
- [ ] A final network failure surfaces a useful error and leaves KOReader responsive.

If these conditions cannot be induced safely on-device, mark them as covered by automated tests rather than forcing provider failures.

## 15. Safe cover validation and replacement

Use a disposable/test EPUB with an existing custom cover.

- [ ] Apply metadata with a valid JPEG replacement cover and confirm the new cover appears.
- [ ] Repeat with PNG or WebP if a live provider supplies one.
- [ ] Confirm only one effective custom cover remains after changing image extension.
- [ ] A deliberately invalid/non-image test payload is rejected before the old cover is removed, if this can be tested safely.
- [ ] An extremely tiny invalid payload is rejected.
- [ ] If a safe way to induce a KOReader cover-write failure is available, confirm the old custom cover remains intact.
- [ ] Confirm cover replacement refreshes KOReader metadata/cover views without damaging the EPUB.

## 16. Write modes, Current → Proposed, and per-book field selection

- [ ] **Replace existing metadata** updates selected custom fields.
- [ ] **Fill missing only** leaves existing populated fields unchanged.
- [ ] Disabled global metadata fields are not overwritten by ordinary Apply.
- [ ] Before Apply, the preview lists only fields that will actually change under the active write mode.
- [ ] Existing values and proposed values are understandable on the Kindle display.
- [ ] Long descriptions are represented as an add/replace action rather than flooding the preview with the entire description.
- [ ] **Choose fields for this book…** opens a temporary selection starting from the current global defaults.
- [ ] Toggle one text field off for a single book and use **Apply selected**; confirm that field is not written.
- [ ] Toggle Cover off for a single book and confirm text can apply without downloading/replacing the cover.
- [ ] Test cover-only Apply selected where practical.
- [ ] After the one-off Apply, reopen global Metadata fields and confirm the saved global defaults were **not** changed.
- [ ] Ordinary **Apply** continues to use the saved global field/cover defaults.
- [ ] A one-off selection with no applicable text fields and Cover disabled reports a no-op rather than creating an unnecessary override.
- [ ] One-step Undo correctly restores a change made through **Apply selected**.
- [ ] A metadata-write failure, if safely induced, is reported instead of crashing the plugin.
- [ ] EPUB file contents are not modified.

## 17. One-step undo and provenance

Use disposable/test EPUBs and verify both the "existing override" and "no existing override" cases.

- [ ] Apply metadata to a book that already has KOReader custom metadata and a custom cover.
- [ ] **Undo last metadata update** becomes available for that book.
- [ ] Undo restores the exact previous custom metadata values.
- [ ] Undo restores the exact previous custom cover.
- [ ] After successful undo, the undo action is no longer available until another apply.
- [ ] Apply metadata to a book with no prior custom metadata/cover, then undo it.
- [ ] Confirm undo removes the newly created custom metadata/cover overrides instead of leaving empty/approximate replacements.
- [ ] Apply twice to the same book; confirm one undo returns to the state immediately before the second apply, not all the way back to the original EPUB state.
- [ ] Restart KOReader after an apply; confirm the one-step undo record is still available and can restore the prior state.
- [ ] Confirm undo backup files are kept under the Metadata Scraper cache/undo directory rather than inside the EPUB.
- [ ] Confirm the plugin refuses to mutate the book if an undo snapshot cannot be created.
- [ ] Confirm **Last match details** shows source/provider ID, score/confidence, ISBN when available, edition/format when available, fields written, match reasons, timestamp, and plugin version.
- [ ] After undo, **Last match details** returns to the previous recorded match when one existed, or disappears when there was no previous plugin match.
- [ ] Exercise more than one test book and confirm undo operates on the selected/current book only.

## 18. Two-phase batch mode, threshold presets, and skip-already-matched

Use a small temporary folder before testing a larger library.

- [ ] Default threshold remains **Recommended (90%)** after upgrading from an older settings file.
- [ ] Select **Strict (95%)** and confirm the displayed/saved threshold becomes 95%.
- [ ] Select **Permissive (80%)** and confirm the displayed/saved threshold becomes 80%.
- [ ] Return to **Recommended (90%)** and confirm it persists after reopening the menu/restarting KOReader.
- [ ] The first batch confirmation clearly says the **discovery phase makes no metadata or cover changes**.
- [ ] Run discovery on a small folder and confirm no selected book's custom metadata, cover, provenance, or undo record changes during discovery.
- [ ] Discovery detects embedded ISBNs where available.
- [ ] Discovery categorizes results into Ready to apply / Low-or-no match / Already matched / Search failures plausibly.
- [ ] Cancel the **second** Apply confirmation and confirm all books remain unchanged.
- [ ] Repeat discovery and choose **Apply**; confirm only Ready-to-apply entries are processed.
- [ ] Exact ISBN ebook-compatible matches can be proposed at the 90% threshold.
- [ ] A different valid ISBN cannot be proposed even when title/author are exact.
- [ ] Explicit print/audiobook format conflicts cannot be proposed at any of the 80/90/95 presets.
- [ ] Other low-confidence/conflicting matches remain in Low/no match rather than being written.
- [ ] **Skip already matched in batch** is enabled by default.
- [ ] Place a previously matched book in the test folder and confirm discovery leaves its current metadata/provenance untouched when skip-matched is enabled.
- [ ] Confirm the already-matched book is skipped before provider querying rather than being searched and discarded later, where this can be observed safely.
- [ ] Disable skip-matched and confirm the book is eligible for normal discovery again.
- [ ] Folder processing remains non-recursive.
- [ ] Maximum file limit is respected.
- [ ] Final applied/not-applied/already-matched/search-failure/apply-failure totals are plausible.
- [ ] One provider failure does not prevent healthy-provider results from being considered for the next files.
- [ ] A successfully applied batch book receives its own undo snapshot/provenance record.
- [ ] Undo records remain bounded rather than growing without limit across a larger batch.

## 19. Updater compatibility and SHA-256 design

Do not publish an actual v0.1.3 release merely to test the branch.

- [ ] **Check for updates…** still reads the latest *published* GitHub Release, not this development branch.
- [ ] The development build identifies itself internally as `0.1.3`.
- [ ] `update.json` lists every runtime file required by the current plugin.
- [ ] `scripts/generate_update_manifest.py` runs successfully on a release checkout after runtime files stop changing.
- [ ] Running the script with `--check` succeeds after hashes are generated.
- [ ] CI regression tests confirm a SHA-256 mismatch aborts before installed plugin files are touched.
- [ ] CI regression tests confirm a manifest missing required hashes is rejected.

### Important release-flow rule

Before the final v0.1.3 tag is created, generate a `sha256` map for its runtime files so the tagged manifest is internally complete and subsequent release tooling can verify it consistently.

Do not hand-edit file hashes. Generate them from the exact release commit/runtime tree.

## 20. Automated checks

The branch GitHub Actions workflow must be green before merge. It covers:

- Lua 5.1 syntax check for every `.lua` file.
- `tests/run.lua` — core/provider regressions and provider status hooks.
- `tests/hardening.lua` — retry, image validation, writer isolation, malformed records.
- `tests/diagnostics.lua` — secret redaction/support bundle.
- `tests/matcher_safety.lua` — conflict safeguards, confidence, author normalization, and edition-format evidence.
- `tests/edition_batch.lua` — EPUB media-kind wiring, two-phase batch UI guards, provenance edition fields, and Amazon binding/edition parsing.
- `tests/updater_integrity.lua` — SHA-256 updater staging/abort behavior.
- `tests/lifecycle.lua` — Current/Proposed calculation and byte-for-byte undo snapshot/restore behavior.

- [ ] Latest branch-head CI run is green after the final runtime/doc/build change.
